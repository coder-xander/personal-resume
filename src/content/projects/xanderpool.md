## 项目背景

xanderPool 是现代 C++ 并发设计的开源实践项目。核心库只使用 C++20 标准库，以头文件形式提供，围绕任务、工作线程、调度和结果组织接口。

与 Ropedia 的产品项目分开维护，用于实践通用基础库的 API 设计、对象生命周期和并发行为。

独立设计并实现 xanderPool，以现代 C++ 组织任务、执行线程、工作窃取、任务组与异步结果，作为并发基础库实践。

## 架构设计与实现

- 封装函数、成员函数、Lambda 和仿函数等可调用对象，支持单任务及批量提交。
- 通过 TaskResult 与 std::future 提供异步返回值、阻塞等待和超时等待。
- 为每个 Worker 维护本地双端队列，空闲线程从其他 Worker 窃取任务。
- 加入 TaskGroup，组织作用域内的任务等待、取消和异常传递。
- 提供固定线程与动态伸缩模式，管理空闲线程回收，并用运行计数帮助观察负载分配。

## 架构思路

将任务描述与执行、工作线程与队列、结果读取与任务组管理分别建模。明确共享所有权、锁顺序与取消语义，把调度、生命周期和结果传播拆成可分别检查的模块。

## 关键实现与取舍

本地任务按 LIFO 取出，窃取端按 FIFO 取出，用两个队列方向组织任务分配。双端队列由互斥锁保护。

线程回收先在管理锁内移除对象，再到锁外停止并等待线程，避免回收和工作窃取形成锁顺序冲突。任务和结果使用共享所有权管理，但调用方仍需保证线程池和任务所引用对象的生命周期。

任务优先级目前作为元数据保留，工作队列没有按优先级重新排序。High、Normal、Low 用于表示任务属性，严格优先级调度留待后续实现。

## 测试与使用边界

项目提供 Google Test 测试，覆盖任务提交、双端队列、窃取、任务组、取消、异常、超时和线程回收等主题。测试与压力样例用于检查具体并发行为，性能比较需要固定负载和可重复的基准。

TaskResult 的结果读取具有 std::future 的一次性语义；TaskGroup 取消尚未开始的任务，并等待已经运行的任务结束，不会强行中断正在执行的函数。
