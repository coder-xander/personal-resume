## 项目背景

设备分散运行后，当前在线状态不足以解释现场发生了什么。平台需要同时呈现设备状态、远程操作、升级任务与历史记录，并能把用户操作和设备回执对应起来。

我参与并持续开发 Go 后端和 Vue 前端，维护设备接入、业务能力与发布流程。

## 我负责的部分

- 通过 MQTT 接入遥测，使用 WebSocket 更新控制台状态，开发分组筛选、日志诊断、录制控制和 OTA 管理。
- 处理设备遥测合并、升级队列、下载与安装阶段调度、延迟进度回报和任务恢复。
- 参与 SQLite 到 PostgreSQL 的数据库演进，调整查询和索引，校验历史数据并验证恢复。
- 将操作、请求与设备响应关联到审计记录，维护按组件发布、版本追踪和回滚流程。

## 关键实现

设备操作是异步过程，请求受理不能直接当成设备执行成功。我把任务标识、状态变化与设备回执建立关联，避免延迟消息把较新的升级状态退回旧阶段。

数据库迁移同时检查表数据、历史 JSON 和索引行为。发布则区分源码、镜像与线上健康，保留版本及产物对应关系。

## AI 运维助手

平台集成 Vera 运维助手。我接入 Lark 对话、ADK 工具编排与 MCP 设备能力，将实时权限检查和设备事实核对放在服务端。智能体通过已有业务接口执行工具，不用对话推测代替设备响应。

## 交付与验证

已有数据库集成、并发检查、生产健康与发布产物校验记录。设备侧操作仍按功能分别验收；例如删除路径的 UI 与约束检查，不等于已经对真实生产设备完成全部后续动作验证。
