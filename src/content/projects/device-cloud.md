## 项目背景

设备分散运行后，当前在线状态不足以解释现场发生了什么。平台需要同时呈现设备状态、远程操作、升级任务与历史记录，并能把用户操作和设备回执对应起来。

我独立设计并实现 Device Cloud 的整体架构、Go 后端、Vue 前端与发布体系，统一设备接入、远程操作、数据管理和运维入口。

## 架构设计与实现

- 通过 MQTT 接入遥测，使用 WebSocket 更新控制台状态，开发分组筛选、日志诊断、录制控制和 OTA 管理。
- 处理设备遥测合并、升级队列、下载与安装阶段调度、延迟进度回报和任务恢复。
- 设计并实现 SQLite 到 PostgreSQL 的数据库演进，调整查询和索引，校验历史数据并验证恢复。
- 将操作、请求与设备响应关联到审计记录，维护按组件发布、版本追踪和回滚流程。

## 架构思路

Core 统一持有业务数据、设备任务与权限，Web 负责控制台交互，EMQX 承接设备消息，Vera 通过受控接口调用平台能力。以异步任务和设备回执关联状态，用审计和发布清单连接用户操作、设备执行与线上版本。

## 关键实现

设备操作是异步过程，请求受理不能直接当成设备执行成功。我把任务标识、状态变化与设备回执建立关联，避免延迟消息把较新的升级状态退回旧阶段。

数据库迁移同时检查表数据、历史 JSON 和索引行为。发布则区分源码、镜像与线上健康，保留版本及产物对应关系。

## Vera Agent 与平台能力

我将 [Vera Agent](../vera-agent/)作为独立运维服务设计并实现。它通过 ADK 与 MCP 使用 Core 提供的设备能力，复用平台身份、实时权限与审计，不另建一套设备控制规则。Web 操作和 Agent 操作使用同一业务边界，设备结果都由任务与回执确认。

## 交付与验证

已有数据库集成、并发检查、生产健康与发布产物校验记录。设备侧操作仍按功能分别验收；例如删除路径的 UI 与约束检查，不等于已经对真实生产设备完成全部后续动作验证。

## 在产品链路中的位置

平台连接[设备核心](../device-core/)、[OTA](../firmware-ota/)和[工厂工具](../factory-tool/)，贯穿设备出厂、运行、维护与档案管理。
