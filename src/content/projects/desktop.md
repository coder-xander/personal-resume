## 项目背景

上位机需要将设备连接、实时监看、采集控制与数据管理放在同一个应用中。USB、局域网、窗口切换和网络抖动，还会影响预览与控制状态。

独立设计并实现 Ropedia Desktop，覆盖 Go 后端、Wails 桌面桥接、React 界面、实时数据处理与三平台交付。

## 架构设计与实现

- 统一 USB 与局域网连接流程，核对设备身份，管理状态轮询、健康检查和重新连接。
- 接入四路 WebRTC 视频，通过 DataChannel 展示 IMU 与音频波形，分别组织设备采集和电脑录制。
- 将原始 Zenoh 消息保存为 MCAP，提供时间回放以及 ROS 2 MCAP、SQLite3 bag 导出。
- 维护 macOS、Windows 与 Linux 的平台包、原生依赖和校验信息。

## 架构思路

按设备连接、控制、实时预览、原始录制和离线导出划分模块。Go 后台持有连接与租约，前端负责交互和显示，原始数据保存独立于渲染。窗口生命周期、网络恢复和录制状态分别管理。

## 关键实现

浏览器计时器会受到最小化和窗口切换影响，因此连接维护与预览续租放在 Go 后台。连接失败经过确认后再恢复，旧会话的迟到结果不会覆盖新连接。

网络恢复不会自动开启录制，HTTP 超时后的控制操作也不盲目重试。预览、设备录制和电脑录制各自拥有状态和生命周期。

数据导出保留原始 H.264 编码、消息内容和来源时间，不为了界面展示转换成 JPEG，也不把显示增益写回原始记录。

## 交付与验证

交付覆盖三平台的软件包，macOS 有正式安装版与 USB 连接验证。Windows 与 Linux 的静态包和运行库检查，与实际 GUI 和设备连接测试分别记录。
