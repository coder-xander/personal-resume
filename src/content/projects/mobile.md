## 项目背景

移动端是现场设备操作入口，需要把设备连接、配置、预览和采集任务放进一个连续流程。应用切换、蓝牙重连、网络变化和设备异步响应都会影响用户看到的状态。

我独立设计并实现 Ropedia Mobile，从 React Native 应用结构、连接与会话管理，到设备控制、原生能力接入和构建交付。

## 架构思路

界面、业务状态、连接会话和设备协议分别管理。连接层处理 BLE 与网络通信，业务层组织设备与任务状态，界面根据状态展示可用操作。设备控制复用 Device Core 的契约，移动端负责平台生命周期与交互流程。

## 架构设计与实现

- 组织设备发现、BLE 连接、状态读取和无线配置，衔接网络侧预览与控制入口。
- 实现采集控制、录制状态与结果上报，处理预览入口、连接异常和操作可用性。
- 接入原生连接服务与视频预览能力，将平台资源生命周期与应用业务状态关联。
- 组织登录、用户、任务与设备页面，以及应用 API、会话、国际化和界面组件。
- 建立 Expo Prebuild、Pods 与 iOS Simulator 的本地构建入口，管理原生目录和环境要求。

## 关键实现

连接可用、录制可用和预览可用分别判断。预览入口先检查设备与网络条件，采集操作根据设备状态处理，界面不会把连接成功直接当作录制已开始。

停止录制、读取设备结果和任务上报按顺序衔接。设备侧响应保留自己的状态，网络失败需要显示实际失败阶段，避免重复操作或把未知结果展示为完成。

## 交付与验证

应用包含设备控制、预览、录制与任务流程，以及对应的状态与组件测试。本地 Simulator 构建、签名发布和 BLE、视频、录制的实机验收分别检查。

## 在产品链路中的位置

Mobile 与 [Desktop](../desktop/)是同一套设备能力的不同操作入口，共用 [Device Core](../device-core/) 的控制规则，并与 [Cloud](../device-cloud/) 的任务和设备数据衔接。
